A simulation can solve cleanly and still be wrong.

SimProof checks your solver files before their numbers reach a report. Every value it reports is traced to the file and line it came from, and can be re-checked at any time.

Get early access Trace a report

Early access. Works with Ansys Mechanical and MAPDL.

Most simulation errors are in the setup, not the solver

Ansys, Abaqus and Nastran are reliable numerical tools. What usually goes wrong is what they were given.

Wrong inputs solve cleanly

A pulsed load sampled at one instant, a modulus entered in GPa in a millimetre model, a missing convection face. The solver converges, the contour plot looks plausible, and the number in the report is wrong.

Report numbers have no trail

Values are copied from screenshots into Word. When a customer asks two years later where a stress came from, nobody can name the run, the file or the node.

Checking does not scale

AI agents and surrogate models will produce far more results than engineers can review by hand. Regulators already ask for credibility evidence: the US FDA finalized its guidance for medical device submissions in November 2023, built on ASME V&V 40.

The first real case

On a commercial Ansys thermal study, the static_time_dependent_load check found steady-state models in which 5 to 7 of 10 heat loads were switched off at the solve instant. The first report built on those results was wrong. The check also reported each load's cycle mean, which was the correction the study needed.

From solver file to signed-off number

Four steps, each one deterministic. A language model can explain a finding; it never makes one.

  1. 1

    Read

    Readers turn input decks, solver logs and result files into one solver-neutral study. Every value keeps its file, its line or node, and the file's SHA-256 fingerprint. Anything a reader can't parse is listed in the report, never guessed.

    ds.dat, solve.out, file.rth
  2. 2

    Check

    Checks are plain Python with no language model in the loop. Each has a written spec, cites the sources its method rests on, and returns the evidence behind its finding.

    static_time_dependent_load: fail
  3. 3

    Report

    The report template can only print a number together with its evidence tag. An appendix lists the source file, location and fingerprint behind every tag.

    33.33 mW/mm^2 [E8]
  4. 4

    Verify

    simproof verify re-reads a finished report and compares every tagged value with its evidence. Edited numbers and numbers without a tag are flagged.

    tagged_values: 10, mismatches: 0

Click a tag to see where its number came from

This is the checks table that simproof report wrote for the synthetic test model in the SimProof repository, with its values unedited. Each tag opens its row of the evidence appendix and the line of the input deck it was read from.

    Solver
    
          
    Ansys Mechanical and MAPDL: input deck, solver output, .rth and .rst result files
    
          
    Checks
    
          
    Six deterministic checks, listed below
    
          
    Reports
    
          
    Markdown, with an evidence tag on every number and an appendix listing each tag's source
    
          
    Re-checking
    
          
    simproof verify compares a finished report with its evidence
    
          
    Interfaces
    
          
    Command line, and an MCP server for Claude Code, Claude Desktop and other MCP clients
    
          
    Where it runs
    
          
    Offline, on your own machine
    
        
    

        
    
          
    Checks
    
          
    A check is marked validated once it has reproduced a hand-audited result on a real model.
    
        
    
        
    
          
    
            
              
    CheckWhat it catchesStatus
    
                
            
              
    
                Time-varying loads in a static solvestatic_time_dependent_load
                A steady-state solve that evaluates pulsed or cyclic load tables at one instant instead of over the cycle.
                Validated
              
    
              
    
                Global conservationglobal_balance
                Heat or force in does not equal heat or force out: missing or double-counted loads, loads on the wrong faces, unconverged solutions.
                Validated
              
    
              
    
                Mesh convergencemesh_convergence
                A result that would still change on a finer mesh, measured with the Grid Convergence Index across two or three meshes.
                Validated
              
    
              
    
                Solver errors and warningssolver_messages
                Runs that reported errors, and warnings nobody has reviewed.
                Implemented
              
    
              
    
                Unit system knownunit_system
                Models whose unit system or temperature scale can't be determined, so no number can be given a trustworthy unit.
                Implemented
              
    
              
    
                Result fields readresults_available
                Studies whose result files are missing or unreadable, so nothing about the results can be reported.
                Implemented
